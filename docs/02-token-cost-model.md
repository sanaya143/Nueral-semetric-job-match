# Token Cost Model: Deep Dive

- **Status:** Estimate v1.1 (2026-11-05). Updated with your decisions D-016 (API embeddings and rerank), D-018 (cost caps) and D-019 (dev budget). To be replaced by measured numbers in Phase 2.
- **Cost caps (D-018):**
  - Production: ≤ $0.20 per match run and ≤ $0.003 per CV. Alert at 80%, hard stop at 100%.
  - Development: LLM spend capped at $50/month (D-019). Phase 2 bake-offs are estimated at $10–30.
- **Why this exists:** at Phase 1 approval, token cost was singled out for a closer look. This document breaks the cost down by step, finds where the money actually goes, stress-tests the assumptions, and sets a token budget policy.

## 1. Headline findings

1. **The funnel is the whole game.** Running a mid-tier LLM over every CV for every job costs 68× more than the funnel at 1K candidates, and about 68,000× more at 1M (§6). Funnel cost per match run stays flat as the corpus grows.
2. **Two steps make up most of the bill:**
   - **Escalation to the mid tier is about two-thirds of per-CV cost.** A 10% escalation rate costs about twice as much as small-model extraction of all CVs combined.
   - **Stage-4 deep evaluation is ~72% of per-run cost (before the fee).** Sonnet-tier calls on the top 10 candidates outweigh everything else.
3. **Reasoning ("thinking") tokens are the biggest hidden risk.** They are billed as output tokens. If a model reasons at 3× its visible output, costs rise ~160–170% per CV and per run (§5). The Phase 1 estimate assumed low effort (0.2×), and the model has to be configured to actually stay there.
4. **Some things matter less than they look:**
   - CV length: 4K-token CVs add only +16% per CV.
   - The OpenRouter fee: about 5%.
   - Which *small* model does extraction: about $360–1,300 per million CVs.

   Pick the small model on quality, not price.
5. **Recommended target profile:** ~$0.0026 per CV and ~$0.16 per match run, with self-hosted embeddings and reranking. The **MVP runs on API embeddings and reranking (no GPU, D-016)**: ~$0.0030 per CV, which is at the $0.003 cap, and ~$0.167 per run. That means the embedding API has to be chosen with price in mind (§4.4). That is 35% below the Phase 1 estimate, with no quality trade-off assumed (§4). Two changes get us there:
   - **Section-level escalation:** re-extract only the low-confidence section with the mid tier, not the whole CV.
   - **Lazy deep evaluation:** deep-evaluate the top 5 eagerly; candidates 6–10 are evaluated only when a recruiter opens them.
6. **Realistic monthly token spend is small:**
   - Mid-size staffing firm: ~$125/month (MVP configuration).
   - 1M-CV IT services firm: ~$710/month (§7).

   Infrastructure ($300–4,000/month) and human labelling will cost more. Token cost still has to be *guarded*, because a misconfigured effort level or K can multiply it quickly.

## 3. Baseline assumptions

| Input | Baseline value |
|---|---|
| CV text | 2,000 tokens |
| Extraction instructions + schema | 1,500 tokens (not cached by default — may be under the model's minimum cacheable prefix) |
| Extraction output (structured JSON) | 1,500 tokens |
| Reasoning/thinking tokens | 0.2× visible output (low effort); billed as output |
| Escalation to mid tier | 10% of CVs |
| Embedded tokens per CV | 3,000 (self-hosted ⇒ $0 marginal) |
| JD intake | 4,000 in / 2,000 out (mid tier) |
| Rubric (cached across candidates) | 1,500 tokens |
| Evidence pack per candidate | 2,500 tokens |
| Verify / deep-eval output | 600 / 1000 tokens |
| Shortlist sizes | verify top 50, deep eval top 10 |
| Report narratives | 10 per run, 1200 in / 300 out |
| NL search | 800 in / 400 out parse + verify top 20 |
| Gateway fee | 5.5% (OpenRouter credit purchase) |

Conservative choices built into the model:
- Every match run re-pays JD intake. In practice the requirement atoms are reused across re-runs.
- Every run is costed at full price. In practice, version-keyed result caching means a re-run pays only for new or changed candidates.
- A changed profile is re-extracted in full.

### 4.4 Routing profiles

| Profile | Extract / verify / deep-eval models | Per CV | Per match run | Per NL search |
|---|---|---|---|---|
| Lean (open small models) | qwen-flash / qwen-flash / sonnet-5.5 | $0.0017 | $0.135 | $0.0037 |
| Baseline (Phase 1 estimate) | haiku-5.5 / haiku-5.5 / sonnet-5.5 | $0.0040 | $0.252 | $0.014 |
| Target (self-hosted embed/rerank) | haiku-5.5 / haiku-5.5 / sonnet-5.5 | $0.0026 | $0.161 | $0.014 |
| MVP (Target + API embed/rerank) | haiku-5.5 / haiku-5.5 / sonnet-5.5 | $0.0030 | $0.167 | $0.014 |
| Quality-max | haiku-5.5 / sonnet-5.5 / opus-5.5 | $0.0098 | $2.03 | $0.366 |

- **Lean** (cheap open small models) halves per-CV cost. It is viable only if it passes the Phase 2 extraction-quality gate.
- **Target** is the recommended routing once embeddings and reranking are self-hosted.
- **MVP** is Target with API embeddings and API reranking, because no GPU is available (D-016). This is the configuration we build first. It costs ~$0.0030 per CV, which sits **right at the $0.003 cap** (D-018). To create headroom:
  - choose an embedding API at ≤ $0.05/M tokens (a $0.02/M model gives ~$0.0027 per CV), or
  - make the extraction prompt cacheable (~$0.0027 per CV).

  Per run it costs ~$0.167, which is 16% under the $0.20 cap.
- **Quality-max** costs ~8× more per run, and $0.37 per natural-language search. Use it only for offline evaluation and gold-set labelling, never for interactive search.

## 8. Token budget policy (enforced in the Model Gateway)

| Call | Tier | Max input | `max_tokens` (output incl. reasoning) | Effort / thinking | On budget breach |
|---|---|---|---|---|---|
| CV extraction (role, project and achievement units only) | small | 6K | 2,000 | off | Truncate pack → retry once → flag for review |
| Escalation (only the units whose quotes failed) | mid | 3K | 800 | off; if refused, low + 1,024 reserve | Flag, keep small-model result |
| JD → requirement atoms | mid | 6K | 1,500 | off; if refused, low + 1,024 (the recruiter confirms every atom) | Fail visibly; recruiter edits manually |
| Verification (only atoms it can still change) | small | 4.5K | 700 | off | Mark "unverified", keep retrieval rank |
| Deep evaluation (strengths cite evidence refs) | mid | 5K | 1,000 | off; if refused, low + 1,024 | Fall back to verification verdicts |
| Report narrative | small | 1.5K | 400 | off | Template-only report |
| NL search parse | small | 1K | 300 | off | Keyword + vector search without atoms |

`max_tokens` is about 2× the largest output measured on the synthetic set (`scripts/token_profile.py`, [docs/eval/token-profile.md](eval/token-profile.md)). Billing is on actual tokens; the cap bounds what each budget check reserves (D-024).

Further rules:
1. **Budgets.** Per-tenant monthly budget and per-run budget (target: ≤ $0.20 per run, ≤ $0.003 per CV). Alert at 80%, hard stop at 100%, with an admin override.
2. **Escalation is per section, not per CV.** Target escalation rate ≤ 10%, tracked weekly.
3. **Deep evaluation is lazy beyond the top 5.** Further candidates are evaluated on demand when opened. Adaptive K: skip deep evaluation when the score gap between ranks is decisive.
4. **Caching:**
   - Put the stable rubric and instructions first and the candidate content last.
   - Make sure the cached prefix meets each model's minimum cacheable length. Short prefixes silently won't cache.
   - At Sonnet prices, a missed rubric cache on deep evaluation adds about 9–11% per run.
5. **Reasoning control.** Set effort or thinking explicitly on every call. Never rely on provider defaults.
   - Claude Haiku 5.5 defaults to *medium* effort with adaptive thinking on. Thinking can be disabled only at effort `high` or below.
   - Claude Sonnet 5.5 rejects `thinking: disabled`; it uses `between_tools` or low effort instead.
   - Checked against OpenRouter's reasoning docs on 2026-11-10:
     - Claude rejects `effort: "none"`; `reasoning: {enabled: false}` maps to thinking disabled.
     - An effort becomes a budget of `max(min(max_tokens × ratio, 128K), 1024)`, with ratio 0.2 for low. So `low` on an 1,800-token cap allowed up to 1,024 hidden tokens.
   - The gateway sends `enabled: false` on every call. If a model refuses (a free HTTP 400), the gateway retries once at `low` with 1,024 extra output tokens, re-checked against the budget, and remembers the model. Whether Sonnet 5.5 accepts thinking-off through OpenRouter will be confirmed on the first real call; the **Thinking** column on the Costs page shows it.
6. **Every call is metered.** Log model, input tokens, cached tokens, output tokens, reasoning tokens, cost and latency per stage per run. The admin dashboard shows cost per CV, cost per run, and tokens per stage, with p50/p95.

## 9. Phase 2: replace estimates with measurements

1. Run 200 gold-set CVs through 3 small models (plus the mid tier for escalation). Measure actual input, output and reasoning tokens, and extraction quality (field-F1).
2. Run 20 gold-set JDs through the full funnel at Target settings. Measure per-stage tokens, latency and cost against ranking quality (nDCG@10, precision@10).
3. Compare deep evaluation on Haiku 5.5 versus Sonnet 5.5. If Haiku holds quality on the gold set, per-run cost drops by about 69% (§5).
4. Verify OpenRouter prompt-cache hits, reasoning-parameter mapping, and batch-API availability.
5. Update `cost_model.py` inputs with the measured values, regenerate this document, and record the final budgets in the decision log.
